dead-lock
-----------------
A deadlock occurs when two or more execution contexts (processes, threads, IRQ contexts) wait forever for resources held by each other, so no one can make progress.
Lock protects data, sleep delays unlock — that blocks the system

Thread A              Thread B
--------              --------
lock(A)               lock(B)
lock(B)   ← waits     lock(A)  ← waits

avoid dead-lock
------------------
Always acquire locks in the same global order
Avoid holding multiple locks
Never sleep while holding a lock
Reduce lock scope

Deadlock occurs when circular lock dependencies exist. In kernel we avoid it using strict lock ordering, minimizing lock scope, never sleeping while holding spinlocks, using trylock, lockless mechanisms like atomic or RCU, and tools like lockdep.

Sleeping while holding a lock is dangerous because the task may be descheduled while still owning the lock, preventing other tasks from acquiring it. This can lead to deadlocks, system stalls, or kernel panics. In particular, spinlocks must never be used with sleeping operations, and in interrupt context sleeping is not allowed at all because the scheduler cannot run.

What happens?
-------------------------
Task A acquires the lock
Task A goes to sleep
Task B tries to acquire the same lock
Task B blocks
Task A is sleeping → not running
Nobody can release the lock
💥 System is stuck
This is a deadlock or system stall

Spinlocks are used in atomic contexts like ISR where sleeping is not allowed.
Mutex is a sleeping lock used in process context where blocking is allowed.
Semaphore allows multiple holders and is useful for resource counting.
Atomic variables provide lock-free synchronization for simple shared data.
RCU is used when read performance is critical and readers must not block.

🔹 Mutex
A mutex is a sleeping lock with ownership, allowing only one holder at a time.

🔹 Semaphore
A semaphore is a counting synchronization mechanism that allows multiple holders.

Mutex is a sleeping lock with strict ownership and priority inheritance, used for mutual exclusion. 
Semaphore is a counting mechanism without ownership, mainly used for resource management.

Mutual exclusion means:
At any time, only ONE thread/process can enter the critical section.

Resource management means:
Managing access to a limited number of identical resources.
More than one thread can enter
But not more than available resources

Producer first waits for an empty buffer slot using semaphore, then uses mutex to safely write into the shared buffer, and finally signals the consumer that data is available.
Consumer waits for available data using semaphore, safely reads the buffer using mutex, and then signals producers that space is available.

Even if no other interrupt exists, sleeping in ISR is not allowed because ISR has no process context and cannot interact with the scheduler. Instead, we defer work to a bottom half or threaded interrupt.

store a value in a particular bit positions
-------------------------------------------------------
STEP 1: How many bits?
------------------------------------------
number of bits = (end - start + 1)

Example:
Bits 2 to 5
5 - 2 + 1 = 4 bits

🧠 STEP 2: Create base mask of 1s
------------------------------------------
Create n 1s where n = number of bits.

For 4 bits:
1111  (binary)

(1 << n) - 1

Example:
(1 << 4) - 1 = 0b1111

🧠 STEP 3: Shift mask to correct position
------------------------------------------
Shift left by the start bit.

mask = ((1 << n) - 1) << start;

Example (bits 2–5):
mask = ((1 << 4) - 1) << 2;

Binary:

0000 1111  << 2  =  0011 1100

So:
MASK = 0x3C
MASK = ((1 << (end - start + 1)) - 1) << start;

STEP 4: What operation do they want?
------------------------------------
Clear bits
data &= ~mask;

Set bits (force to 1)
data |= mask;

Store value
data = (data & ~mask) | ((value << start) & mask);

Extract value
value = (data & mask) >> start;

final result
------------
MASK = ((1 << (end - start + 1)) - 1) << start;
data = (data & ~MASK) | ((value << no.of bits(n)) & MASK);

No scheduler
No stack for rescheduling

No sleeping
No mutex
No semaphore (sleeping)
Only spinlocks / atomics allowed

Kernel design rule

what happened in ISR
------------------------------------------
“ISRs use spinlocks because they cannot sleep. When a spinlock is held in ISR, other CPUs or processes spin until it’s released. Interrupts are disabled to avoid deadlocks.


What exactly happens when ISR acquires a spinlock?
Let’s say ISR does:

Internally:
CPU executes an atomic instruction
(e.g., test_and_set, cmpxchg)
Lock state becomes LOCKED
ISR enters critical section
Interrupts are typically disabled locally
(using spin_lock_irqsave())

This prevents:

Same lock being re-acquired

-------------------------------------------
A critical section is a part of code that accesses shared data and must not be executed by more than one execution context at the same time.

Execution context can be:

Thread

In DMA context:
A sync error can happen if cache is not properly synchronized with DMA memory, leading to stale or corrupted data.

Common reasons:
1️⃣ Cache not flushed before DMA write
2️⃣ Cache not invalidated after DMA read
3️⃣ Race condition between interrupt and process context
4️⃣ Missing locks (mutex/spinlock)

In Linux DMA:
Use dma_sync_single_for_cpu()
Use dma_sync_single_for_device()

One-line safe answer:
Sync errors happen due to improper cache management or missing synchronization during DMA or concurrent access.



Frame drop issues happen when the system cannot process incoming frames fast enough, so buffers overflow and frames get discarded.

Common reasons:
1️⃣ Buffer overflow (insufficient buffers)
2️⃣ DMA not fast enough
3️⃣ CPU overload
4️⃣ Interrupt latency high
5️⃣ Bandwidth issue (SPI/I2C/MIPI slow)
6️⃣ Improper synchronization

In camera/video drivers:
If user space doesn’t dequeue buffers fast enough, kernel drops frames.

How to debug:
Check buffer count
Monitor CPU usage
Check interrupt timing
Verify DMA completion
Strong one-line answer:
Frame drops usually occur due to buffer starvation, high latency, or insufficient processing speed.



A page fault occurs when a process tries to access a virtual memory page that is not currently mapped in physical memory.
A page fault occurs when a process accesses a virtual address that is not currently mapped to physical memory.
Page fault happens when a virtual address has no valid physical mapping in the page table.
Page fault occurs only when a process accesses a virtual page that is not yet mapped in physical memory.
Page fault happens only when the required page is not present in RAM, not on every memory access.


What happens next:
CPU triggers page fault exception
Kernel checks if access is valid
If valid → loads page into RAM (from disk or allocates new)
If invalid → segmentation fault


Virtual memory is not physically created like RAM. It is an abstraction created by the CPU and MMU using page tables.

Where does it exist?
Virtual memory exists in the process address space and is managed by the kernel using page tables stored in RAM.

Important:
Page tables are in RAM
MMU hardware does the translation
Virtual addresses are generated by CPU
Strong interview one-liner:
Virtual memory is created by the OS using page tables in RAM, and the MMU maps virtual addresses to physical memory.


Demand paging is a memory management technique where pages are loaded into RAM only when they are actually accessed.

Meaning:
Memory is not loaded fully at process start.
When a process accesses a page for the first time → page fault occurs.
Kernel loads that page into RAM.
Then execution continues.

Why use it?
Saves memory and improves efficiency.
Strong interview one-liner:
Demand paging loads a page into memory only when it is needed, triggered by a page fault.


FROM WHERE to RAM
---------------------
Pages are brought into RAM either from disk (swap or executable file) or newly allocated by the kernel.
If the page belongs to a file or was swapped out, it is loaded from disk. If it is anonymous memory like malloc, the kernel allocates a fresh page in RAM.

Memory allocated in probe() must be freed in remove() using the corresponding free API. If devm_ managed APIs are used, the kernel automatically releases memory when the driver unloads.

Difference of Mutex, semaphore, spinlock
-----------------------------------------------
A mutex allows only one thread to access a shared resource at a time.
If lock is unavailable → thread sleeps
Mutex provides mutual exclusion and puts the thread to sleep if the lock is unavailable.

A spinlock provides mutual exclusion by busy-waiting.
If lock is unavailable → CPU spins
Spinlocks are used when sleeping is not allowed, such as in ISRs

A semaphore is a counter-based synchronization mechanism.
Binary semaphore (0/1)
Counting semaphore (>1)
Semaphores control access to a limited number of identical resources.

Spinlocks waste CPU but are fast; mutex saves CPU but may sleep; semaphores control counts.

// SWAP 6 AND 9 BIT POSITIONS

#include <stdio.h>

int swap_6th_9th_bit(int x)
{
    int bit6 = (x >> 5) & 1;   // 6th bit (position 5)
    int bit9 = (x >> 8) & 1;   // 9th bit (position 8)

    // Swap only if bits are different
    if (bit6 != bit9) {
        x ^= (1 << 5) | (1 << 8);
    }

    return x;
}

    printf("Before swap: %d\n", x);
    printf("After  swap: %d\n", swap_6th_9th_bit(x));

    return 0;
}

int main() {
    int arr[] = {7, 7, 2, 5, 2, 1, 3, 4, 6};
    int n = sizeof(arr) / sizeof(arr[0]);

    int res[n];   // result array
    int res_size = 0;

    for (int i = 0; i < n; i++) {
        int found = 0;

        for (int j = 0; j < res_size; j++) {
            if (arr[i] == res[j]) {
                found = 1;
                break;
            }
        }

        if (!found) {
            res[res_size++] = arr[i];
        }
    }


	// Sort digits (Bubble Sort)
    for (int i = 0; i < res_size - 1; i++) {
        for (int j = 0; j < res_size - i - 1; j++) {
            if (res[j] > res[j + 1]) {
                int temp = res[j];
                res[j] = res[j + 1];
                res[j + 1] = temp;
            }
        }
    }


    // Print result
    for (int i = 0; i < res_size; i++) {
        printf("%d ", res[i]);
    }

    return 0;
}

// Simple Stack Implementation using Array (C)

#include <stdio.h>
#define SIZE 5

int stack[SIZE];
int top = -1;

// Push operation
void push(int value) {
    if (top == SIZE - 1) {
        printf("Stack Overflow\n");
        return;
    }
    stack[++top] = value;
}

// Pop operation
int pop() {
    if (top == -1) {
        printf("Stack Underflow\n");
        return -1;
    }
    return stack[top--];
}

// Peek operation
int peek() {
    if (top == -1) {
        printf("Stack is empty\n");
        return -1;
    }
    return stack[top];
}

int main() {
    push(10);
    push(20);
    push(30);

    printf("Top: %d\n", peek());
    printf("Popped: %d\n", pop());
    printf("Top: %d\n", peek());

    return 0;
}

struct Node* removeNthFromEnd(struct ListNode* head, int N)
{
	
	Struct Node dummy;
	dummy.next = head;
	
	Struct Node *fast = &dummy;
	Struct Node *slow = &dummy;
	
	for(int i=0; i<=N; i++){
	if(fast == NULL) return head;
	fast = fast->next;
}

while(fast != NULL){
Fast = fast->next;
Slow = slow->next;
}
Node *del = slow->next;
slow->next = del->next;
Return dummy.next;
}
